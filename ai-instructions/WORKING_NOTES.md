# Working notes

## Decisions made (with reasons)
- **2026-10-19, Mikkel:** build **from scratch** (beside HyperFrames/OpenFilm, not on Remotion/Revideo); name **dolly** (CLI `dolly`); **Apache-2.0**; **public** repo MikkelBlom/dolly. Apache-2.0 also makes borrowing HyperFrames (Apache-2.0) code straightforward, with attribution in NOTICE.
- **2026-10-20, Mikkel: old global skill retired.** ~/.claude/skills/motion-promo-video is now a short redirect to dolly (the plugin skill, or skills/dolly/SKILL.md in this repo); the original is archived in ~/.claude/skills-archive/motion-promo-video/.
- **GLOBAL_CLAUDE.md is git-ignored** because the repo is public; Mikkel's global rules are his private instructions.
- **Capture = `Page.captureScreenshot` PNG on chrome-headless-shell, GPU flags, one browser per worker.** beginFrame works on Windows (shell 151) but gave no speed gain (117 vs 106 fps). Tabs in one browser serialise (1×8 = 38 fps vs 8×1 = 76).
- **Default workers = ¾ of logical cores, max 16** (12 here; measured knee 12 → 107 fps, 16 → 113).
- **Motion blur = compositor tree accumulation** (N scene iframes in nested 50/50 `plus-lighter` groups, one screenshot). Flat 1/N stack rejected (8-bit quantisation per layer).
- **Smear past the cap**: frames needing > 32 samples whose motion is mostly camera get an SVG Gaussian blur on the world layer along the pan (σ = gap/√12), with a filter region sized to the visible world each frame (huge regions make Chromium drop the layer; objectBoundingBox clips the world).
- **Chromium flags that matter for correctness**: `--force-gpu-mem-available-mb=12000` (default budget dropped layers on 32-document hosts), `--disable-lcd-text`, `--disable-low-res-tiling`, `--disable-checker-imaging`. `RENDERER` in `frames.ts` is part of every cache key; bump it when capture changes pixels.
- **No `will-change`** anywhere (lint error): Chromium keeps such layers at their first raster scale → render-order-dependent text.
- **Inactive scenes use `display:none`**; `tf()` sets `visibility: ""` (not "visible") so hidden ancestors still hide children.
- **HTML-in-Canvas is not the fast path today** (~28 ms per sub-frame). Watch item for Chrome 157.
- **npm workspaces**, Node 24 type stripping (no build step); esbuild for scene bundles and the player UI.
- **Lint tuned against the approved Price Peek film** (taste as rules): odometer transitions and live values (≥ 3 text states) aren't reading-time text; font size measured where text rests; outermost entering element counts once; static = < 3 px/s; mobile size only for vertical/square; contrast error only < 3:1.
- **Determinism is checked on rendered state, not pixels**: `__dolly.fingerprint()` lists every visible element's computed transform, opacity, colours, filter, text and box; `dolly diff` compares those between two render orders and names what differs. Pixel differences with identical state are Chromium raster noise (a faint render-history-dependent AA fringe on moving text that persists with CPU raster and `--disable-partial-raster`) and are reported as harmless. Golden tests use a pixel criterion that tolerates that noise (fail only if > 0.002 % of channels change by > 128 levels or mean > 0.4).
- **The blur host waits for every leaf's `__dolly.ready`**, not just mount: each document's startup ends with render(0), which otherwise could land after the first sub-frame render and leak t=0 into the average (found by the acceptance test as ghosts in blurred stills).
- **Warm daemon runs the CLI's own commands in-process** (2026-10-20): the client forwards argv + cwd, the daemon swaps `io.out/err` to the connection and calls `main()`; one code path, so `--json` output is byte-identical (checked: info/still/sheet/lint cold vs warm, and error output). Rejected: a separate RPC API per command (would duplicate logic, violates "CLI is the source of truth"). Commands are serialised (a page renders one frame at a time; `process.chdir` per request is safe only because of that). The daemon ignores `--workers` (its pool size is fixed at start); `bench` is never forwarded (it measures a cold pool).
- **Page reload, not browser restart, on change**: `Session.refresh()` rebuilds on every command (~40 ms warm, so edits can never be missed even if the watcher is late) and reloads pages only when the bundle/aspect/size/nmax changed. Reloaded pages give the same pixels as fresh browsers within Chromium's known raster noise (≤ 1 level on 3 of 8 blurred stills; cold-vs-cold shows the same).
- **Debugging port = 0 + `DevToolsActivePort`** (2026-10-20): the old `9500 + random(300)` per process collided with a long-lived daemon's 12 ports; the new process then *attached to the daemon's browser* through `/json/version` (found as a hang: a cold `still --blur` left 32-iframe hosts inside the daemon's Chromiums). Latent before the daemon too (two concurrent dolly processes).
- **Fully cached renders start no browser**: scene metadata is cached per (globalHash, bundleHash, aspect) in `.dolly/cache/meta1-*.json`, written by every session that probes. `render()` opens a lazy session and calls `ensureWorkers()` only for a missing plan or missing frames; the blur host is warmed only if a missing frame needs it.
- **Experiments pin the Price Peek baseline to commit 2a2b909**: the KRW working copy was edited by another session during this one (end-card timings +0.15 s, uncommitted).

## Open technical questions
- sRGB (compositor) vs linear-light blur: compare visually on the whip before choosing the default; HTML-in-Canvas gives linear light when it gets faster.
- Root cause of the residual raster history noise (suspect layer squashing/assignment hysteresis). Worth a minimal repro for a Chromium bug if it matters.
- Fully cached render is now ~7.5 s with no browser: what is left is PNG decode + NVENC p7 re-encode of 1,800 frames. Caching the encoded segment per frame range (or `-c copy` concat when nothing changed) would make it near-instant.
- Thermal soak test (≥ 3 min sustained, AC vs battery) not done; renders so far are < 1 min.
- Plugin installed for Mikkel (2026-10-20, user scope, from the GitHub marketplace MikkelBlom/dolly): the installed copy's bin/dolly shim and MCP server both work. The install is pinned to a commit; after pushing changes run `claude plugin marketplace update dolly` and `claude plugin update dolly@dolly`.
- The alpha (ProRes/WebM) path is implemented but has not been rendered and checked.

## Concerns
- Compositor accumulation relies on unspecified Chromium behaviour (blend precision of render surfaces). `experiments/verify-blur.ts` compares against a CPU float average; keep running it after Chromium updates.
- `fontCss` (network fonts) makes renders depend on Google Fonts being reachable: **on 2026-10-20 fonts.gstatic.com reset connections for several minutes** (curl too) and every cold Price Peek command failed with `NetworkError` until it recovered. The daemon reduces exposure (fonts load once per browser) but does not remove it; self-host for Price Peek once Mikkel OKs downloading the font files.
